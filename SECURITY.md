# Security Policy

## Scope

This repository contains prompt and configuration templates. It does not provide an authentication system, browser driver, entitlement checker, secret store, or security sandbox.

## Safe use

- Keep all real credentials, passwords, access tokens, cookies, session data, verification codes, and authentication files out of prompts, configuration files, commits, logs, screenshots, and issue reports.
- Do not delegate personal data, protected business data, unpublished research, internal documents, server details, complete private code, or private datasets to a web session.
- Replace the symbolic capability names only in a private configuration location. Do not commit account-specific tool names or endpoints.
- Treat an unavailable, failed, or uncertain eligibility check as not eligible.
- Require explicit human confirmation for sign-in, account switching, verification, payment, private-file upload, public publishing, and other external side effects.
- Review current product behavior and official security guidance before deployment. A prompt is not a security boundary.

## Reporting a security issue

Do not include secrets, personal data, private source code, or exploit payloads in a public issue. Use the repository owner's private security-reporting channel if one is enabled. Otherwise, provide only a minimal non-sensitive description and wait for a safe contact method.
